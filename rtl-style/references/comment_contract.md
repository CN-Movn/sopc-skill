# 中文注释硬约束

本文件定义 `rtl-style` 生成或实质修改 Verilog RTL 时的最低注释标准。它不是“有空就写”的建议。

## 1. 模块顶部必须有中文说明块

新模块必须在 `module` 声明前给出中文头部。以下为最低必填字段：

```verilog
// -----------------------------------------------------------------------------
// 模块名称：packet_scheduler
// 功能说明：完成 XXX；不负责 XXX。
// 时钟复位：clk_xxx，100/200 MHz；rst_n 为低有效同步复位（若已知频率必须写明）。
// 接口说明：输入/输出握手语义、关键配置与状态接口。
// 数据流与延迟：输入 fire 后经过 N 级流水，在什么条件下产生输出；吞吐能力。
// CDC 说明：本模块是否单时钟；若存在跨域，写明同步/FIFO/握手机制。
// 时序设计：关键组合逻辑如何拆级；ready/高扇出/大 fan-in 如何处理。
// 边界说明：计数器回卷、短帧、异常、flush、drop 等关键边界。
// -----------------------------------------------------------------------------
```

不知道的事实不要编造。可以写“频率由上层约束，本模块不假设固定频率”，但不能直接省略字段。

## 2. 哪些内部逻辑必须有中文注释

以下结构至少要在代码块前解释“为什么这样做”：

- 非平凡 FSM 或状态转换分组；
- AXI/AXIS `fire`、backpressure、skid、flush；
- 计数器终值、回卷、off-by-one 边界；
- RAM/FIFO 读写边界；
- 多时钟 CDC 同步结构；
- pipeline stage 的职责与增加的延迟；
- 为缩短组合路径而进行的预译码、寄存、分级比较、树形归约；
- priority 逻辑（必须说明为什么顺序优先级是功能需求）；
- 错误/丢弃/恢复路径；
- 容易被误改的协议不变量。

## 3. 注释质量

好注释：

```verilog
// 第 1 级只完成头字段预译码，把“字段比较 + 状态选择”拆开，避免同周期形成深组合锥。
```

弱注释：

```verilog
// 判断头字段。
```

不要逐行翻译语法。注释应表达接口语义、边界、不变量、硬件推断和设计取舍。

### 清晰、合理、适量

- 不按文件行数、注释行数或注释密度评价质量；一个准确的块级注释可以覆盖一组紧密相关的 RTL。
- 对显然的赋值、标准样板和已由信号名完整表达的动作，不重复叙述。
- 同一设计意图只在最接近其硬件实现的位置说明一次；接口合同放模块头，局部取舍放对应逻辑块前。
- 禁止为了通过 checker 复制“组合逻辑”“寄存数据”“状态判断”等泛化注释。无法说明边界、原因或硬件后果时，通常不需要该注释。
- checker 只检查最低结构覆盖，不能判断注释是否真实、准确或足量；交付前仍需人工/Agent 语义复核。

## 4. 修改已有模块时

- 如果只改一行简单常量，不要求重写整份文件注释。
- 如果新增 FSM、pipeline、CDC、RAM/FIFO、复杂握手或改变主要数据流，必须补齐相关中文注释。
- 如果现有模块没有顶部说明，而本次属于“实质修改”，补上头部说明。

## 5. 交付自检

交付前确认：

- [ ] 顶部说明块存在且不是空模板。
- [ ] 新增非平凡 `always` 块有中文意图说明。
- [ ] pipeline/CDC/握手/计数边界均有中文说明。
- [ ] 没有为了数量逐行翻译语法、复制泛化注释或重复同一事实。
- [ ] 注释与最终 RTL 一致，没有保留旧逻辑描述。
