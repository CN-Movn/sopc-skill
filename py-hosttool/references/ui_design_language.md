# UI 设计语言

## 1. 设计目标

这套界面不是消费类应用风格，而是“长期运行、信息密集、现场可读”的工业调试工具：

- 关键状态一眼可见；
- 控件密度较高但不拥挤；
- 操作区、诊断区、日志区层级明确；
- 颜色表达状态，不用颜色装饰无关内容；
- 窗口缩放后保持可用，不依赖固定坐标。

## 3. 尺寸与间距

- 标题栏：36 px；按钮：46×35 px；外框圆角：正常 5–6 px，最大化时 0。
- 内容外边距：10–12 px；GroupBox 内边距：7–9 px；控件间距：4–8 px。
- 按钮最小高度约 25 px；输入控件最小高度约 24 px。
- 串口设置侧栏：235–260 px；协议工作台左栏：固定约 535 px。
- 诊断仪表盘左栏：最小约 640 px；右栏：最小约 800 px。

## 4. 层级

1. 自定义标题栏：应用身份与窗口控制。
2. 主功能区：用水平 `QSplitter` 划分“控制/协议”和“串口/诊断”。
3. 功能模块：用 `QGroupBox` 命名，用 `QTabWidget` 控制信息密度。
4. 实时状态：底部状态栏或网格，展示连接、协议、刷新、RX/TX/帧数。
5. 详细历史：日志、导出文件、诊断快照。

## 5. 状态表达

- 连接灯只表达连接状态；错误详情仍写进状态栏或日志。
- 诊断卡片使用动态 property，例如 `severity=error/notice/stale`，通过 QSS 改边框。
- 表格行可使用浅色背景表达严重度；不要用高饱和纯色覆盖大面积文本。
- `[ERROR]` 优先于 `[WARN]`，`[WARN]` 优先于 `[OK]`，不要依赖标签出现顺序。
- “无数据”与“硬件错误”必须区分：通信缺失是 stale，不应直接标成设备故障。

## 6. 字段布局

- 少量配置采用 `QFormLayout`。
- 对称的双列参数采用 `QGridLayout`，明确列最小宽度与 stretch。
- 上下两个独立 Grid 需要视觉对齐时，先计算共同 label/button 的最大 `sizeHint()`，再统一列最小宽度。
- 大段 HEX 使用 `QPlainTextEdit`；需要局部着色时使用 `QTextEdit`。
- 长日志禁止 Qt 二次自动换行；HEX 行由程序按固定字节数布局。

## 7. 不应做的事

- 不用大量绝对坐标、固定像素位置或手工拖拽拼界面。
- 不为“好看”增加渐变、阴影、动画，避免影响调试性能和信息清晰度。
- 不在一个页面同时铺开所有高级参数；使用 Tab、折叠或独立子窗口。
- 不用单一红色表示断连、未采集、协议错误和硬件错误。
