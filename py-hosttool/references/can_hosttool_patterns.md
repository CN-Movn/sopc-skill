# CAN 上位机通用模式

本 reference 记录 `can_hosttool_v2.0.3` 中适合其他上位机复用的工程机制。来源工程仅作为设计输入，业务协议、字段映射、CAN ID、厂家 SDK、设备标识、现场日志、用户设置、EXE 和构建产物均未进入 skill。

## 协议来源核对

- 以用户确认的协议文档、寄存器表、RTL/固件定义或抓包说明为 source of truth。
- 将长度字段语义、最大报文、字节序、CRC/checksum 覆盖范围、poly、init、refin/refout、xorout 和输出字节序逐项显式记录。
- golden vectors 应来自固件实现、独立工具或人工计算，不能只由待测 Python 编码器反向生成。
- 表格内部矛盾、未闭合字段和测试缓存不能由上位机自行“解释成已定案”。
- 来源映射检查脚本应只读输入，并输出源文件哈希、映射记录数、枚举组和差异；未解决语义继续列为未解决。

## Transport 与请求生命周期

- GUI 只提交命令和消费事件；底层句柄只在 worker 线程创建、读写和关闭。
- 命令队列与接收事件队列都要有界。过载时应停止产生新数据、走统一断连路径并显式报告，不能静默丢帧。
- `open`、`close`、`shutdown` 应幂等，并为控制命令保留优先路径，避免周期发送饿死关闭操作。
- 所有异步结果带 connection/workflow generation；断连、重连或取消后，旧 generation 的数据只能丢弃或作为诊断事件。
- 等待“驱动接受发送”和等待“对端业务回复”是两个不同超时。驱动调用尚未返回时，不能报告设备回复超时。
- 写命令、脉冲和其他不可幂等操作禁止因超时自动重放；没有去重键或确认机制时，迟到响应只能隔离，不能证明其归属。
- 仿真/回放后端必须实现同一 transport 契约；回放模式不得把录制的 TX 再发往硬件。

## 记录与回放

- JSONL 作为无损源记录，保存时间、方向、通道、原始 bytes、解析结果、错误和可选设备时间戳；CSV 只作为便于人工查看的派生物。
- 记录线程与 GUI、transport 线程解耦。GUI 只提交条目，记录队列满时显式返回失败并设置可显示错误。
- 回放至少支持按方向过滤，并在结束时正常触发 closed/finished 事件。
- 原始字节不得因 ASCII 显示、HEX 格式化或 CSV 导出而丢失。
- 日志与抓包可能包含敏感信息；进入仓库前必须脱敏，录制目录和用户设置不得成为 Skill 资产。

starter template 中的通用实现见 `assets/template/py_hosttool_template/hosttool/recording.py`，它不包含来源工程的协议或字段。

## 分层完成状态

上位机应分别记录以下层级，不能用下一层成功替代上一层：

1. 本地参数校验通过；
2. 命令进入发送队列；
3. 驱动/串口 API 接受发送；
4. 对端发送了可识别的链路回复；
5. 协议解析和校验通过；
6. 业务状态或回读证明操作完成。

通道在线灯只由符合项目定义的完整有效回复点亮。任意 RX、本地 TX、旧回显或缓存包都不能单独作为设备业务正常的证据。

## UI 与恢复

- 双通道/多节点状态应独立维护，一个通道回复陈旧不能熄灭仍新鲜的另一个通道。
- 显示切换不应隐式发送请求；手动读取和周期采集要使用明确的目标选择。
- 断连时统一清除 busy、timer、pending request、差分基线和旧的在线指示。
- 自动流程使用显式 step 和 generation；取消或失败后停止后续步骤，并丢弃晚到回调。
- 离屏测试可验证布局约束、控件边界、点击区域和状态机；真实 Windows 的拖动、缩放、DPI 和置顶仍需单独验证。

## 验证阶梯

按证据强度分别报告：

1. 纯函数 golden vectors 与协议恢复测试；
2. transport/worker 的队列、超时、断连和 shutdown 测试；
3. 模拟 transport 的端到端流程；
4. offscreen GUI smoke 与布局检查；
5. onedir 构建和 frozen EXE smoke；
6. 真实 Windows UI 手工检查；
7. 经授权的真实设备联调。

前一层通过不能证明后一层通过。设备联调脚本必须要求显式 `--execute` 或等价授权，并避免在无确认时自动发送不可逆命令。

## 复用配方

1. 从 template 复制外壳、worker 和通用 recorder/replay。
2. 用新项目协议重建 parser、golden vectors、client、registers 和 workflows。
3. 为 fake/loopback transport 实现同一契约。
4. 定义发送接受、链路回复、解析成功和业务完成的状态文案。
5. 运行协议、记录回放、GUI smoke 和关闭路径测试。
6. 先 onedir，再 frozen smoke，最后按授权做真实设备验收。
